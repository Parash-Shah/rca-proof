# Delivery roadmap

All metrics are targets until measured. Do not publish example counts as achieved results.

1. **Failure lab and deterministic causal search (implemented):** Java 21 reactor, Spring Boot services, LocalStack SQS/DynamoDB, observable payment side effects, crash hook, exhaustive search through three factors, evidence artifact and tests.
2. **Incident and evidence API (implemented):** PostgreSQL/Flyway, incident state machine/history, normalized evidence intake and timeline, leased background investigations, per-trial checkpoints, bounded sandbox budgets and persistent proof APIs. Automatic telemetry collectors remain future work; see [the API contract](incident-api.md).
3. **Classification and organization-aware planning (implemented):** persisted classification and planning APIs, synthetic permission interventions, timeout abstention, versioned organization snapshot, catalog alternatives, policy gates and no-change outcomes. See [scope and demo](classification-and-planning.md). The full taxonomy exists; automatic remediation planning currently supports bounded duplicate-payment and HTTP retry cases, alongside expected-denial no-change outcomes.
4. **Hypotheses and reusable scenarios (partial):** the [HTTP retry-storm adapter](http-retry-lab.md) uses an actual HTTP client and separate WireMock dependency, with provider request receipts and measured candidate comparisons. Its verification adapter adds latency, shared caller deadlines, one-hop remaining-budget propagation and broken connections. Local behavioral models remain separately labeled. Separate causal investigations for transport incidents, multi-hop deadline enforcement, richer telemetry correlation and additional distributed service implementations remain future work.
5. **Remediation verification (implemented for payment and bounded GET retries):** separate payment and HTTP retry suites, durable verification jobs, incident replay, nearby faults and candidate-specific coverage gates. Reports say VERIFIED_IN_SANDBOX and require independent CI evidence for certification. Retry verification does not inherit payment certification. See [payment scope](remediation-verification.md) and [retry scope](http-retry-lab.md).
6. **Certification (implemented for two declared local-lab contracts):** source/patch/archive/dependency binding, 22 payment or 16 HTTP retry checks, signed candidate/scenario/suite identity, trusted CI evidence, immutable certificates and stale-certificate detection. Both contracts support review preparation. Dirty builds and unconfigured authorities remain blocked. See [certification contract](remediation-certification.md).
7. **Review integration (implemented adapter):** exact certified commit/base checks, persisted previews, draft PR creation, retry reconciliation and an approved pre-review certification workflow. Live publication requires configured GitHub credentials and a real certified candidate. Never auto-merge or deploy. See [review integration](review-integration.md).
8. **Evaluation and observability (evaluation partial; local observability validated):** 32 controlled variants across eight local behavioral models, durable metrics and provisioned dashboards. A three-outcome smoke check validates API/Prometheus agreement and all seven Grafana panel queries, including from a fresh source-package build and database. One-command startup, source packaging and a release checklist are available in the [release runbook](release-runbook.md). Broader distributed-system ground truth and a reviewed external release remain next work. The AWS FIS adapter is optional.

AI can later propose hypotheses and patches. It cannot set invariant outcomes, proof states, policy decisions, test results or certification gates.
